# HOT 집중 운영 · 우리 집 매운맛 광고

## 상품과 노출
- 웹 우선. HOT 1~8단계; 기존 1~5단계 의미 유지. RICH·SWEET의 데이터를 삭제하지 않고 공개 페이지는 HOT으로 이동한다.
- 광고는 매장별 대표 매운 상품 **1개**. 사업자·소유권·사진·가격·위치가 확인된 메뉴만 신청 가능하다.
- 월 **8,000원은 최저 입찰가**다. 예산은 VAT 별도이며 최고 예산 적격 업체의 실제 낙찰 예산을 결제한다. 예: 8,000원 입찰 → VAT 포함 8,800원.
- 사용자가 보고 있는 위치 15km 이내, 유효한 유료 광고 중 1곳만 목록 최상단. 사진 왼쪽 위 `광고` 배지. 검색 결과·실시간 영업상태를 보장하거나 조작하지 않는다.
- 지역별 월 1개 광고. 겹치는 지역에서는 최고 낙찰 예산 → 가까운 매장 → 먼저 제출한 입찰 순으로 1개만 반환한다.

## 광고관리 과정
1. `/admin/ads`에서 지역 중심 좌표·지역명·노출 월을 개설한다. 모집 반경 15km, 월 시작 48시간 전 입찰 마감.
2. `/advertise`에서 로그인한 점주가 소유권이 확인된 대표 상품 1개, 지역·월·예산·신라면 대비 체감 매운맛과 약관을 제출한다. 제출만으로 결제·노출되지 않는다.
3. 관리자는 소재를 승인 또는 반려한다. 수정된 입찰은 다시 검토 대기 상태가 된다.
4. 마감 후 서버가 승인된 적격 입찰을 최고 예산 → 최종 제출 시각 → ID 순으로 선정한다. 관리자 임의 금액 또는 임의 업체를 낙찰자로 지정할 수 없다.
5. 낙찰자만 24시간 이내(노출 시작 전까지) 단건 결제. 미선정 업체는 과금하지 않는다. 미결제는 기한 뒤 제외하고 차순위를 재선정한다.
6. PortOne의 PAID·KRW·주문번호·금액·LIVE KCP_V2 채널을 서버에서 검증하고 service_role 전용 RPC로 기록한 뒤에만 월 광고가 활성화된다. 브라우저의 성공 메시지는 증거가 아니다.
7. 해당 월 첫날 00:00~다음 달 첫날 00:00 KST 노출. 자동갱신 없음; 다음 달 새 입찰. 월 종료·소유권/신뢰 제한·취소/환불 시 슬롯에서 자동 제외.
8. 관리자는 모집/광고를 중단할 수 있다. 유료 건은 환불 확인 필요 상태로 남는다. 전액 환불은 PortOne CANCELLED·전액 취소금액을 확인한 뒤 기록한다. 부분 환불은 별도 심사·결제기관 처리 후 기록이 필요하며 현재 UI에서 지원하지 않는다.

## 접근 경계
- `public.is_admin()`의 기존 founder 권한으로 관리자 기능을 제한한다. 일반 점주는 본인 신청/주문만 조회한다.
- 모든 광고 테이블에 RLS. 일반 계정은 테이블 직접 쓰기·노출 활성화·환불 기록이 불가능하다.
- Public 슬롯 API는 광고 메뉴 ID와 체감 기준만 반환하며 입찰자/예산/결제정보를 공개하지 않는다.
- 낙찰과 주문 처리는 지역 모집 행 잠금과 고유 인덱스로 단일 승자/단일 주문을 보장한다.

## 연결과 출시 조건
- 네이버 지역검색은 상호·주소·좌표 등 매장 검색 보조다. 공식 API는 메뉴·사진·가격·고추 아이콘·매운맛·영업시간을 제공하지 않는다. `heatVerified=false`이며 지도에 추정 메뉴를 생성하지 않는다. 검색당 최대 5개. 전체 네이버 플레이스를 일괄 수집한 것으로 표시하지 않는다.
- 서버 환경: `NAVER_SEARCH_CLIENT_ID`, `NAVER_SEARCH_CLIENT_SECRET`.
- 광고 결제는 **PortOne V2 + NHN KCP V2 카드 일반결제**. 기존 Paddle 상품과 분리한다.
- 서버 환경: `HOT_AD_PORTONE_STORE_ID`, `HOT_AD_PORTONE_CHANNEL_KEY`, `HOT_AD_PORTONE_API_SECRET`, `HOT_AD_PORTONE_WEBHOOK_SECRET`, `SUPABASE_SERVICE_ROLE_KEY`. 실계약·광고상품 심사·LIVE KCP_V2 채널을 확인한 뒤 `HOT_AD_PORTONE_LIVE_ENABLED=true`로 활성화한다. 비밀키는 저장소·브라우저·채팅에 넣지 않는다.
- KCP 광고 상품 계약/카드사 심사와 PortOne 상점·채널 발급은 대표 확인 단계다. 현재 연결·실결제 성공은 미검증이다. 동의 없이 가입/유료계약/결제하지 않는다.
- PortOne 콘솔 V2 웹훅을 `https://hot.nowgo.space/api/hot-ads/webhook`에 등록한다. 원문 서명 검증 후 결제조회 API를 다시 호출해 서버 주문의 금액·상점·채널·LIVE·통화를 비교한다. 서명 및 취소 이벤트, 중복 이벤트, 모바일 복귀 누락과 재전송을 sandbox에서 검증한 뒤 실채널 승인한다.
- 리다이렉트 `/advertise/payment`에서 로그인 세션으로 같은 주문의 결과를 재확인한다. 서명된 웹훅도 독립적으로 반영하여 브라우저를 닫았다고 결제 연결이 누락되지 않게 한다. 테스트 채널의 PAID는 운영 광고 권한을 만들지 않는다.
- Paddle의 공식 AUP는 Advertising Services를 제한하므로 이 상품을 기존 Paddle SaaS/지도 구독으로 위장해 연결하지 않는다.
- DB: `20261012034947_hot_eight_levels_single_product.sql`, `20261012035100_hot_local_ad_slot.sql`.
- 중앙 SPACE의 `/api/owner/featured-menu`도 HOT 8단계 검증을 허용해야 첫 메뉴 등록과 연결된다. 별도 counterpart PR에서 수정한다.

## 회귀 확인
- 예산/동률/결제 위변조·미설정 차단·8단계·NAVER E7 좌표·메뉴와 지역 구분·광고 API 권한 테스트.
- 공개 HOT API에서 2026-10-11 HDD 핫치킨피자 2건 반환 확인. 임시 저장 매운닭고기 피자 1건은 자동 공개하지 않는다.
- 성수동 검색은 주소 geocoder로 지도 이동 후 텍스트 필터를 지역 반경 필터로 바꾼다. 도로명 주소에 `성수동`이라는 글자가 없어도 제외하지 않는다.
- 프로모션 기본 예산을 전체로 변경하여 26,000원 피자가 초기 20,000원 필터 때문에 숨지 않게 한다.

## 네이버 지도와 지역 숫자
- 공개 웹 지도·앱 공용 웹 지도·제보 위치·점주 가입 위치를 NAVER Web Dynamic Map + Geocoding/Reverse Geocoding으로 전환했다. `NEXT_PUBLIC_NAVER_MAPS_NCP_KEY_ID` 또는 `NAVER_MAPS_NCP_KEY_ID`가 필요하며 허용 Web 서비스 URL과 선택 API를 콘솔에서 확인해야 한다. 기존 SPACE의 키 이름만 확인됐고 HOT 키값 및 도메인 허용은 미검증이다.
- 지도 zoom 9 이하 지역, 10~12 구/군, 13~15 동/읍/면, 16 이상 개별 매장. 원 안 숫자는 메뉴 수가 아니라 동일 상호·주소의 공개 매장 수다. 숫자가 커질수록 빨강이 진해진다. 원 클릭 시 확대한다.
- `/api/map-density`는 공개 카탈로그를 전부 읽어 검색·필터·정확한 15km 반경을 적용한다. 목록 페이지의 100개 제한과 독립적이다. 25,000건을 넘어 집계가 불완전하면 전체 숫자로 표시하지 않고 검색 지역 축소를 안내한다. 캐시 30초.
- 도로명 주소만 있는 매장은 동을 임의 추정하지 않고 ‘동 미확인’으로 묶는다. NAVER 전체 맛집 수/외부 추천/검증 완료 수로 표시하지 않는다.

## 현재 인계 상태
- 개발 DB 두 migration 적용과 권한 확인 완료; 운영 DB는 기존 읽기 전용 지시로 자동 승인 심사에서 두 migration 적용이 거절됐다. 운영 데이터 변경 없음.
- 중앙 SPACE counterpart Draft PR121. HOT region-only PR51 Preview는 ignored build step 설정으로 CANCELED이며 READY가 아니다.
- Cloudflare 배포·중앙 main 병합은 NOWGO 담당 범위. 지도 키/실결제 계약/운영 migration 없이 전체 기능이 운영 반영됐다고 표시하지 않는다.

- 무료 운영 정책 migration `20261012051000_hot_free_owner_management.sql`는 운영 소유권·신뢰·탈퇴 차단을 보존하고 HOT의 구독 요건만 제거한다. 개발 DB에는 기존 HOT owner workspace 함수가 없어 이 migration의 DB 실행은 아직 미검증이다. 운영에서는 승인받은 담당자가 기존 workspace 뒤에 적용해야 한다. 실제 상태 변경·소유권 격리·미니홈 동기화를 확인하기 전 완료로 표시하지 않는다.

- HOT 점주 대시보드는 대표 상품 1개만 표시·수정하며 같은 메뉴 ID를 중앙 featured API와 지도 상세 RPC에 사용한다. 기존 고객 제보/다른 품목 데이터를 삭제하지 않는다. 서버 RPC 단일상품 제한 migration 적용 후 직접 RPC 접근도 같은 기준으로 제한한다. 미니홈 사진·가격 및 영업·품절 동기화의 실계정 검증은 미완료다.
- HOT 기존 구독은 자동 해지/환불하지 않았다. 신규 기본관리 구독 시작은 차단하고 기존 구독 조회·해지 경로는 유지한다. 광고 과금은 별도 PortOne 낙찰 주문만 사용한다.
