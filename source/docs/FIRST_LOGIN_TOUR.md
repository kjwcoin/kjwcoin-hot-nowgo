# 첫 로그인 사용 안내 (HOT · RICH · SWEET)

## 동작 순서

1. 지도 컴포넌트가 `FirstLoginTour`를 렌더링합니다. Supabase `onAuthStateChange`의 `INITIAL_SESSION` 또는 `SIGNED_IN`에서 로그인한 사용자 ID를 확인합니다. 비로그인 방문자에게는 표시하지 않습니다.
2. 브라우저 `localStorage`에서 `nowgo:first-login-tour:v1:<taste>:<user-id>`를 읽습니다. 값이 `done`이면 안내를 열지 않습니다. 세 맛 지도는 각각 자기 도메인에서 별도로 완료 여부를 저장합니다.
3. 처음 방문한 회원에게 지도 위 흐린 배경과 **맛집 찾기 / 제보하기** 선택 화면을 엽니다. 맛집 찾기는 검색 → 맛 단계 → 맛 종류 → 메뉴 → 예산 → 지도 결과의 여섯 요소를 순서대로 가리킵니다.
4. 제보하기는 지도 오른쪽 제보 버튼을 가리킵니다. 다음을 누르면 `sessionStorage`에 진행 상태를 남기고 `/suggestion#report`로 이동합니다. 해당 페이지에서 제보 안내와 사진 첨부 칸을 두 단계로 이어서 보여줍니다.
5. **완료** 또는 **건너뛰기**를 누르면 완료 키를 저장하고 진행 상태를 지웁니다. 새로고침 및 같은 브라우저에서 다시 로그인해도 이 계정의 해당 맛 지도 안내는 다시 뜨지 않습니다.

## 라이브러리와 수정 지점

`driver.js@1.4.0`의 `driver({steps, onNextClick, onCloseClick})`을 사용합니다. 단계와 문구는 `components/first-login-tour.tsx`의 `findSteps`, `reportMapStep`, `reportPageSteps`에서 편집합니다. `map-explorer.tsx`는 선택 화면과 지도 단계를, `hot-app.tsx`는 제보 화면 단계를 장착합니다. 색과 모바일 배치는 `app/globals.css`의 `nowgo-tour-*` 규칙입니다.

이 완료 표시는 **현재 브라우저의 계정별 선호 설정**입니다. 다른 기기나 브라우저까지 동기화해야 한다면 사용자 ID와 맛 사이트 키를 기본 키로 하는 서버 테이블과 본인만 읽고 쓰는 RLS 정책으로 대체해야 합니다. 완료 표시는 권한 검증에 사용하지 않습니다. 브라우저 저장소를 사용할 수 없을 때는 반복 표시를 막기 위해 투어를 열지 않습니다.

## 확인 절차

- 로그아웃 지도: 선택 화면 없음.
- 첫 로그인: 선택 화면의 두 버튼과 건너뛰기 동작 확인.
- 맛집 찾기: 6단계의 대상·다음·완료, 새로고침 후 재노출 없음.
- 제보하기: 우측 버튼 → `/suggestion#report` → 폼/사진 안내 → 완료, 새로고침 후 재노출 없음.
- 다른 계정: 같은 브라우저에서도 별도 첫 안내. 모바일과 PC 각각 단계 위치 확인.
